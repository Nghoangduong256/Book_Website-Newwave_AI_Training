# Rule: Coding Conventions

Enforceable rules, not advice. Most are checked by CI; the rest are checked at review.
Source: `plan/BD/BD-00_OVERVIEW.md` §4–§9.

---

## R-C1 · Layering

1. A router function contains only: dependency declarations, a call to **one** service method, and a
   return. No conditionals on business state, no loops over domain objects, no data access.
2. A router MUST NOT import from `repository.py` or `models.py`.
3. A service module MUST NOT import `fastapi` or any `Request`/`Response` type.
4. All SQL and all ORM query construction MUST be inside a repository method.
5. A cross-module call goes service → service. A repository MUST NOT reference another module's
   table.
6. A service method accepts and returns DTOs or domain objects. It MUST NOT accept a database
   session from its caller.

## R-C2 · Module structure

7. Each business module lives in `backend/app/modules/{module}/` with exactly these files:
   `router.py`, `schemas.py`, `service.py`, `repository.py`, `models.py`, `events.py`,
   `permissions.py`, and a `tests/` directory. Add files only when the module genuinely needs them.
8. `permissions.py` declares the module's permission strings as constants. No permission string may
   appear as a literal in a router.

## R-C3 · Naming

9.  Tables `{prefix}{plural_snake}`, using the module's allocated prefix.
10. Columns `snake_case`; foreign keys `{singular_referenced}_id`.
11. Indexes `ix_{table}_{cols}`, unique `uq_{table}_{cols}`, checks `ck_{table}_{rule}`, enum types
    `{module}_{concept}`.
12. DTOs `{Entity}Create`, `{Entity}Update`, `{Entity}Read`, `{Entity}Summary`.
13. Service methods are verb-first: `create_project`, `submit_timesheet`.
14. Background tasks `{module}.{action}`.

## R-C4 · Database

15. Every business table carries the common columns: `id uuid` default `uuidv7()`, `created_at`,
    `updated_at`, `created_by`, `updated_by`, `version`, `deleted_at`. Append-only tables MAY omit
    the mutation columns and MUST say so in a comment.
16. Every foreign key is indexed and declares `ON DELETE` explicitly. Default `RESTRICT`; `CASCADE`
    only for genuinely owned children.
17. Money is `numeric(18,2)` paired with `currency char(3)`. Never a float, never a bare amount. A
    converted value carries its exchange-rate snapshot.
18. Effort and duration in hours are `numeric(8,2)`.
19. Timestamps are `timestamptz`, stored UTC.
20. JSONB is permitted only for genuinely schemaless payloads. If a field is filtered, sorted,
    aggregated or reported on, it is a column.

    20a. **A JSONB column stores Python `None` as JSON `null`, and `'null'::jsonb IS NULL` is
    false.** A query looking for "no value recorded" with `IS NULL` silently misses every row that
    recorded one explicitly. Decide which the column means, and write the predicate that matches.
21. Reads exclude `deleted_at IS NOT NULL` by default. Including soft-deleted rows is explicit and
    permission-gated.

## R-C5 · Migrations

22. One migration per logical change. Autogenerated output MUST be read and corrected before
    committing — never commit it unread.
23. Migrations are forward-only in any deployed environment. A mistake is fixed by a new migration,
    never by editing an applied one.
24. Every migration is safe against a running application: **add first, backfill second, constrain
    third, drop in a later release.** No blocking rewrite of a table expected to grow.
25. Seed and reference data ship as idempotent data migrations. Running a seed twice MUST NOT
    duplicate rows, and there is a test proving it.
26. **A constant a migration imports is frozen the day that migration ships.** A migration that
    imports an enum from application code will do something different next year when that enum
    gains a value, and will then disagree with the database it already wrote. Inline the literal
    values into the migration.

## R-C6 · API

27. `PATCH` is the default for updates. `PUT` only where full replacement is genuinely idempotent.
28. **A PATCH DTO's fields are all optional, and the service applies only the fields that were
    set.** With `exclude_unset`, a form that always sends every field turns an untouched empty box
    into a deletion. The form sends what changed; the DTO's optionality is not a substitute for that.
29. Collections use keyset pagination (`?limit=&cursor=`). Offset pagination requires a stated
    reason and is prohibited on a table expected to exceed ~100k rows.
30. `limit` defaults to 25 and caps at 200.
31. Errors use the RFC 9457 envelope with a stable machine-readable `code`. The message is
    localized; the `code` is not.
32. Mutating a versioned resource requires `If-Match` and returns 409 on mismatch — never a silent
    overwrite.
33. Any operation that can exceed ~2 seconds returns `202` with a job handle. It MUST NOT block the
    request.
34. **HTTP 200 is not success for a job, a saga or a workflow.** The status code says the request
    was accepted; the payload's state field says what happened. Branch on the state field.
35. Filtering uses explicit typed query parameters. No generic query-language passthrough. Only
    whitelisted columns are sortable.

## R-C7 · Frontend

36. Server Components by default. `"use client"` only when state, effects or event handlers are
    required — and then on the smallest component that needs it.
37. **A Server Component importing a function from a `"use client"` module gets a proxy, not the
    function.** The call does not throw; it simply does not run. Constants, type guards and pure
    helpers shared across the boundary belong in their own directive-free module.
38. Server state through TanStack Query only. UI state through Zustand only. Never server data in
    Zustand or UI state in Query.
39. All access to our own API goes through the generated client. No hand-written `fetch` to our own
    endpoints.
40. `any` is prohibited, and so is `@ts-ignore` — use `@ts-expect-error` with a comment if genuinely
    unavoidable.
41. No hard-coded colour, spacing value, radius, shadow, font size or animation duration. Design
    tokens only.

    41a. **A colour class naming a numeric shade must have a token behind it.** If the scale defines
    50/600/700, then `border-warning-200` emits no rule and the property falls back — silently, and
    only in a browser. Soften an existing stop with an opacity modifier instead of inventing one.
42. No hard-coded user-facing string. Everything goes through the i18n layer, and **a string is
    written in every catalogue in the change that introduces it.** A key present in one catalogue
    and missing from another is a screen that renders an English sentence to a Vietnamese reader —
    or renders its own key path to everyone.

    42a. **A translation key that is *data* still has to resolve.** `labelKey: "items.deliveryLog"`
    rendered through `t(item.labelKey)` is invisible to a scanner that reads literal `t("…")` calls.
    If you add a table of keys, add it to the key-coverage test in the same change.
43. Every list and detail screen implements four states: loading skeleton, empty, error with retry,
    and permission-denied.
44. **A route is built from the key the route declares.** If routes are keyed on a human-readable
    code and the hook carries a uuid, a link built from the uuid compiles, typechecks, renders, and
    404s on click. Typecheck cannot catch it — both are strings.
45. Components stay under roughly 200 lines. Beyond that, split.
46. **Never offer a cross-origin file through a plain `<a download>`.** The `download` attribute is
    ignored cross-origin, so a presigned-URL anchor *navigates* instead of saving, and the
    application becomes a browser error page. Fetch to a blob, or route through a same-origin
    endpoint.

## R-C7a · Responsive layout

*Every rule here comes from a measurement. Layout failures are invisible to every other gate:
`tsc`, `eslint` and jsdom have no layout engine, and an app frame with `overflow-hidden` **clips**
an over-wide page rather than scrolling it. Nothing looks broken until someone holds a phone.*

47. **A new screen is not done until it has been measured at 375px.** `ops/responsive.sh /route`
    asserts the one thing that is never intentional: horizontal overflow inside `main`.
48. **A multi-column grid starts at one column.** `grid-cols-3` with no prefix forces three columns
    into 327px. Write `grid gap-4 sm:grid-cols-2 lg:grid-cols-3`.
49. **Wide content scrolls inside its own container; the page never scrolls sideways.** A table, a
    chart or a code block gets its own `overflow-x-auto` wrapper, and then contributes nothing to
    its parent's scroll width.
50. **No fixed width on a control inside a flex row.** `w-56` is 224px that cannot yield. Write
    `w-full sm:w-56`.
51. **Chrome that does not fit is hidden, never shrunk.** Shrinking text to fit is how a 375px
    header ends up with its right-hand controls clipped away.
52. **A row of fields aligns on its controls, not on its boxes.** `items-end` aligns each child's
    box, and a field carrying a description is one line taller — so its input sits a line above its
    neighbours' and the row reads as broken. Use `items-start`.

## R-C8 · Commits and review

53. Conventional commits: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`. One logical
    change per commit.
54. Branch per feature. No direct commits to the default branch.
55. A pull request states which design sections it implements and which requirement IDs it
    satisfies.
56. **Any deviation from a design document is recorded as an ADR in `docs/adr/` and raised as a CR.**
    Silent improvisation is prohibited: it is how the documents stop describing the system.

## R-C9 · Dependencies

57. Versions are pinned and committed in a lockfile. Upgrading requires re-verifying the version is
    current and noting it in an ADR.
58. Adding a dependency requires a one-line justification in the PR description.
59. Before adding any library that makes outbound HTTP calls, **check what it logs at INFO.** Several
    log full URLs, and query strings carry presigned-URL signatures, share tokens and API keys. A
    library's default verbosity is part of its security surface.

## R-C10 · Logging

60. Get a logger only through the application's own `get_logger(__name__)`. Never call the logging
    library's factory directly, and never bind a name onto it at import time — an eagerly-resolved
    logger freezes the defaults and silently emits lines with **no trace id and no secret
    redaction**. Nothing raises.
61. Never log a full URL, a full request body, or a whole request object. Log the path, the method,
    and named fields you chose deliberately.
62. A new sensitive field name goes into the redaction list in the same change that introduces it.
63. One JSON object per line, no exceptions. Half a stream is not queryable.

## R-C11 · Asynchronous work is visible

R-C6 §33 says an operation over ~2 seconds returns `202`. It says nothing about what happens next,
and that omission is reliably worth several user-reported defects per phase — every one reported as
"it says nothing" or "it says the wrong thing", never by a test.

> **A job the user started and cannot see is indistinguishable from a job that never ran.**

64. **A background job persists its own state, and a screen that can start one shows it.** Not the
    request's state — the *job's*. A pending-mutation flag covers the milliseconds of a `202` and
    then goes false while the work runs for minutes. The state must survive a reload and be the same
    for a second viewer, which means it lives in the database, not in a hook. A nullable JSONB column
    carrying `{phase, started_at, finished_at, counts, detail}` is the cheapest shape that works.
65. **Write the phase at every transition, including the ones that are not progress.** At minimum:
    queued (written by the request, *before* it dispatches — the worker may start before the request
    returns), running, then done or failed. A job blocked on something else must say what it is
    waiting for.
66. **A status label MUST NOT describe work that has not started.** `pending` rendered as
    "Extracting…" describes a document that has not been read and may never be.
67. **Every wait is bounded and ends in a state a user can act on.** A job that gives up sets
    `failed` with a sentence naming the likely cause and the next step — never `pending` forever,
    which reads identically to work in flight.
68. **Poll only while something is in flight, and stop by itself.** 3–5 s for a job whose phases are
    seconds-to-minutes; never 1 s, and never forever.
69. **Never invent a percentage.** A bar that fills on a timer sits at 99% for minutes or reaches
    100% before the work finishes. Show a determinate bar only where a real numerator and
    denominator exist — "check 3 of 20" — and otherwise an indeterminate one with no `aria-valuenow`.
70. **A queue is part of the state.** A job can be correct and invisible because it never got a
    worker. Where a queue is shared and jobs are long, distinguish *queued* from *running*, and never
    present a queued job's empty output as a result.
